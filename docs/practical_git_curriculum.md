# 実務向けGit学習カリキュラム

READMEとアプリの演習・対応コマンドを拡充し、Git操作、チーム開発、復旧、GitHubのPR・レビュー・CIを練習できる構成です。アプリの一覧は操作別の16コース、この文書では学習の流れに沿った12章に整理します。

## 現在の状態

既存の7章・39演習に100演習を追加し、現在は139演習です。演習の一覧はREADMEに掲載しています。各演習には実行可能な解答手順を持たせています。

リモートでは、他メンバーの更新を用意した仮想サーバーを使い、pushの拒否からfetch・統合・再pushまでを練習できます。履歴操作では、rebase、cherry-pick、revert、reflog、タグを扱います。競合時には、解消して--continueする方法と--abortで元へ戻す方法を個別に学びます。

GitHub模擬環境では、PR作成からレビュー修正・CI失敗対応・再承認・マージまでを扱います。CIは指定した結果を再現し、実際のジョブを実行しません。

実装済みコマンドも、実際のGitと同じ全オプション・挙動を保証していません。各ファイルの内容を単位とした競合判定など、簡略化した処理があります。

土台の修正状況は次のとおりです。

- 実装済み：確認コマンドでも達成判定を実行する。競合発生時の状態を画面へ反映する。
- 修正済み：「差分の確認」をdiffに変更し、touchについての誤った説明を更新する。
- 実装済み：HEAD、ファイル内容、親コミット、直近のメッセージ列、GitHubの状態に基づく判定。soft／hard resetの課題の誤判定を修正する。
- 検証済み：既存39演習と新規100演習の解答手順。新規演習の初期状態の独立性・再実行も検証する。

## 演習の単位

各演習は「実務での状況」「開始時の状態」「一つの学習目標」「操作後に確認する結果」「段階的なヒント」を持ちます。

最初は一操作ずつ学び、章末で複数の操作を組み合わせます。確認コマンドは実行と出力を、変更コマンドは状態の変化を検証します。別の方法でも目的を満たせる課題は、特定コマンドの使用だけで合否を決めません。

## 学習順序

以下は学習する操作の一覧です。複数の項目を一演習に含む場合もあります。GitHubの9演習でPRの作成・確認、レビューの修正依頼、CI失敗と修正、最新コミットへの承認・再チェック、マージ・クローズを練習し、機能開発の総合演習で組み合わせます。

| 章 | 実務の場面 | 分割する演習 |
| --- | --- | --- |
| 1. 作業開始 | 新しいプロジェクトに参加する | init／clone／configで作者設定／設定の確認／statusで未追跡・変更済み・ステージ済みを区別／.gitignoreで生成物を除外／既に追跡したファイルとignoreの違い |
| 2. 変更を記録 | レビューしやすい変更を作る | ファイル作成／内容編集／diffで未ステージ差分確認／一ファイルをadd／複数ファイルをadd／diff --stagedで記録対象確認／commit／変更の一部だけをadd -p／ステージ後に再編集／rmで削除／mvで名前変更／変更を目的別に分けてコミット |
| 3. 履歴を読む | 変更理由を調べる | log／log --oneline／log --graph --all／showで一コミット確認／二コミット間のdiff／ファイル単位の履歴／メッセージ検索／blameで行の由来を確認 |
| 4. ブランチ | 機能開発を並行する | branchで作成／switchで移動／switch -cで作成と移動／一覧と現在位置の確認／名前変更／統合済みブランチ削除／未統合削除の拒否／未コミット変更がある切り替え／Detached HEADで過去を調査／Detached HEADのコミットをブランチに保存 |
| 5. マージ | 完了した機能を統合する | 統合先への移動／fast-forward／分岐後のマージコミット／--no-ff／--ff-onlyの拒否／同じファイルの競合を発生／競合ファイルの確認／双方の変更を残して解消／解消をaddして完了／merge --abortで開始前へ戻る／ファイル削除と編集の競合 |
| 6. リモート | 他のメンバーと変更を共有する | remote一覧／remote add／URL変更／fetch／ローカルとリモート追跡ブランチの違い／初回pushとupstream／通常push／pullでfast-forward／リモート側の更新でpush拒否／取得して統合後に再push／pull --rebase／リモートブランチの取得と追跡／削除済み追跡ブランチのprune |

| 8. 取り消し | 間違った編集・コミットを直す | restoreで未ステージ変更を戻す／restore --stagedでステージ解除／ファイル単位の取り消し／reset --soft／reset --mixed／reset --hard／三方式のHEAD・index・作業ツリーを比較／commit --amendでメッセージ修正／amendで追加漏れを修正／共有済み変更をrevert／revertの競合を解消・中断 |
| 9. 履歴を整理 | レビュー前にコミットを整える | 最新mainへrebase／mergeとの履歴比較／rebaseの競合解消／rebase --continue／rebase --abort／対話的rebaseでreword／squash／fixup／並び替え／一コミットを分割／共有ブランチを書き換える影響を確認／force-with-leaseで想定外の更新を拒否 |

## 総合演習（7演習すべて実装済み）

1. **初めての機能開発**：取得 → ブランチ作成 → 変更確認 → 目的別コミット → push → PR → レビュー承認・CI → マージ。mainに直接変更を記録しないこと、対象ファイルがリモートへ届いたことを確認する。
2. **他メンバーとの競合**：push拒否 → fetch → 履歴確認 → mergeまたはrebase → 競合解消 → 再push。双方の変更が残ることを確認する。
3. **緊急バグ修正**：作業をstashまたはworktreeで分離 → 修正ブランチでコミット → 必要な保守ブランチへcherry-pick → 元の機能開発を再開する。
4. **レビュー前の整理**：差分を確認 → 不要な変更を取り消す → コミットをまとめる・分割する → 最新mainに追従する。最終ファイル内容とコミット構成を確認する。
5. **誤操作からの復旧**：誤ったresetまたはブランチ削除 → reflogで履歴を調べる → ブランチを作成して救出する。
6. **共有済みの不具合を取り消す**：問題のコミットを特定 → revert → 後続の正常な変更が残ることを確認する。
7. **リリース後の修正**：タグから保守ブランチを作成 → 修正 → 開発ブランチにも移植 → 新しいタグを付ける。

## ブラウザでの再現範囲

すべての演習はブラウザ内で動きます。仮想リモートと他メンバーのコミットを用意しており、ネットワーク・認証・実GitHubアカウントなしで繰り返せます。`simulate review` と `simulate ci` はアプリ専用です。実GitやGitHub CLIのコマンドではありません。

- **通常操作・履歴**：演習で使うオプションを実装しています。外部エディタや任意のシェルは起動しません。対話的rebaseは画面のtodo編集欄、部分ステージングは端末へのy／n／q入力を使います。
- **競合**：主にファイル単位の三方向比較で再現します。実Gitの行単位の自動マージ・すべての競合パターンを保証しません。
- **bisect**：good／badを手動で判定します。第一親の直線履歴を基本にし、実際のプログラムやbisect runを実行しません。
- **worktree**：仮想パスへのcdで独立した作業状態を切り替え、コミットとブランチを共有します。OS上にディレクトリは作りません。
- **sparse-checkout**：基本的なcone形式の対象ディレクトリを指定します。全パターンやsparse-indexには対応しません。
- **submodule**：登録済みの仮想依存リポジトリを使い、初期化・更新・親でのコミット参照を練習します。実ファイルやネットワーク取得は行いません。
- **Git LFS**：install／track、対象パターンと.gitattributesを記録する2演習です。バイナリの変換・アップロードは再現しません。
- **GitHub**：PR・レビュー・保護ブランチ・最新コミットへのCI結果を状態として再現します。Actionsのジョブ、ワークフローYAML、実際のテスト実行は対象外です。

### Git LFSポインタの読み方

実際のGit LFSでは大きなファイルの代わりにGitへポインタを記録します。次は形式を示す例です。oidは内容のSHA-256、sizeは元ファイルのバイト数です。[公式のポインタ仕様](https://github.com/git-lfs/git-lfs/blob/main/docs/spec.md)を参照してください。

```text
version https://git-lfs.github.com/spec/v1
oid sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
size 12345
```

実Gitで確かめる場合はGit LFSを導入した環境の**新しい練習用ディレクトリ**で、`git init` → `git lfs install --local` → `git lfs track "*.bin"` → sample.binを作成 → `git add .gitattributes sample.bin` → `git show :sample.bin` の順で操作します。最後の出力がポインタ、作業ツリーのsample.binが元の内容です。この手順はブラウザ演習の採点対象には含みません。

## 挙動確認に参照する公式資料

- [git push](https://git-scm.com/docs/git-push)：fast-forwardとforce-with-leaseの条件。
- [git fetch](https://git-scm.com/docs/git-fetch)：リモート追跡参照の取得とprune。
- [git stash](https://git-scm.com/docs/git-stash)：未追跡ファイル、applyとpop、競合時の保存。
- [git rebase](https://git-scm.com/docs/git-rebase)：履歴の載せ替え、競合時の継続・中断。
- [git worktree](https://git-scm.com/docs/git-worktree)：独立した作業ツリーと共有参照。
- [git bisect](https://git-scm.com/docs/git-bisect)：good／badによる原因調査。
- [git sparse-checkout](https://git-scm.com/docs/git-sparse-checkout)：作業対象の絞り込み。
- [git submodule](https://git-scm.com/docs/git-submodule)：依存リポジトリの参照管理。
- [Git LFS pointer specification](https://github.com/git-lfs/git-lfs/blob/main/docs/spec.md)：ポインタの形式。
