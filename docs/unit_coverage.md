# ユニットテストのカバレッジ測定

`npm ci`の後に`npm run test:coverage`を実行すると、VitestのユニットテストをV8で計測します。計測対象のテストが失敗した場合はコマンドも失敗します。

出力は次の3種類です。`coverage/`はGitの追跡対象外で、再実行時に置き換わります。

- 端末: ファイルごとの文・分岐・関数・行の実行率と未実行行
- `coverage/index.html`: ブラウザでソースの未実行箇所を確認するレポート
- `coverage/coverage-summary.json`: 全体とファイル別の集計を機械処理できるJSON

## 対象と数値の読み方

`src/**/*.ts`と`src/**/*.tsx`を明示的に対象とし、テストから読み込まれていないファイルも集計します。テスト本体、`.d.ts`、`src/types/`の型定義、テストのためだけに使う`src/engine/test-simulator.ts`は除きます。UIを除外して全体の率を高く見せないようにします。

これはNode環境のVitestが実行した範囲の数値です。`npm test`で別に実行する実GitラボのNode.jsテスト、PlaywrightのブラウザE2E、公開環境のsmokeは合算しません。画面コンポーネントが0%でも、E2Eが実行されていないとは限りません。逆に行カバレッジが高くても、拒否経路・状態の整合性・実Gitとの差が検証された保証にはなりません。

未実行の分岐を読み、利用者に影響する入力や状態遷移がある場合にテストを追加してください。数値を上げるためだけの実装追従テストは追加しません。

## 運用

このPRでは測定コマンドとレポートだけを導入します。最低率の閾値やCIの合格条件は追加せず、通常の`npm test`は従来どおり実行します。測定結果の比較には、同じ対象ファイル・Node/Vitestのバージョン・コミットを記録してください。大幅な依存更新時は`vitest`と`@vitest/coverage-v8`のpeer依存を揃えます。

ロードマップT09のうち計測環境に対応します。ランダム操作による不変条件の検証と、測定後に見つかる未検証経路への対応は別の作業です。
