# 模擬IDの衝突時に履歴を保持する（2026-10-25）

同じ`Math.random()`値が続くと、従来の短いID生成は同じキーを使い、既存コミットや模擬PRのマージコミットを上書きしていました。子が自分自身を親に持つ状態や、以前のsnapshotの消失が再現しました。乱数が0の場合には空のIDも作られていました。

通常の短い模擬IDを維持しつつ、使用済みなら`-1`・`-2`のように空いているsuffixへ進めます。再度乱数を引くループは使わず、乱数を固定しても停止するようにしました。候補が空の場合は`0`を使います。

コミットの予約先にはローカルだけでなく、後からfetch/pushで同じID空間へコピーされる模擬remote内の全コミットも含めます。通常commit・amend・自動merge・replay経由のcommit・模擬PRマージが同じ方針を使います。stashは保存済みstash間でIDを重複させません。取得済みの履歴・reflog参照・stash内容を置き換えないことを確認します。

単体5件は修正前にすべて失敗し、修正後に成功しました。0と0.5の乱数固定、amend、自動merge、未取得remote、既存の模擬PRマージID、stashの保持を検証しています。既存のIDを付け替えるmigrationは不要です。

E05のうちID衝突の防止に限定した修正です。実Gitの内容ハッシュを再現するものではなく、既に壊れた保存状態の復旧、時刻/ID生成器全体の注入、独立した複数ブラウザの履歴を集約する機能は対象外です。
