## 指摘と優先順位

### P1: 状態表示の文字コントラストが不足

- 場所: src/app/game/page.tsxのWorking Directory凡例、src/components/git-graph.tsxのHEADラベル。
- 実測: 凡例の文字と背景は約2.35:1、白文字とHEADラベルの緑背景は約2.54:1。凡例は12px、HEADは10px。
- 影響: ファイル状態や現在位置を読みにくい。小さい通常文字の基準4.5:1を満たさない。[W3Cのコントラスト基準](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。無効ボタンの薄い文字はこの指摘の対象ではない。
- 対応: 凡例の文字を明るくし、HEADラベルは濃い背景または暗い文字で十分な差を取る。
- 推奨: `$impeccable colorize`。

### P2: スマートフォンのフッターが開始ボタンの背後に隠れる

- 場所: src/app/page.tsxのabsolute bottom-6のフッター。
- 実測: 390px画面でスクロール後、開始ボタンのy=769〜829に対しフッターはy=801〜821。アニメーション完了後（opacity=1）にも重なる。320pxでも重なった。
- 影響: フッターが読めない。開始ボタン自体はクリックできる。
- 対応: フッターを通常の文書フローに戻し、ボタンとの間隔を確保する。
- 推奨: `$impeccable layout`。

### P2: HEADラベルの背景が文字幅に足りない

- 場所: src/components/git-graph.tsxのブランチラベル幅。
- 実測: mainの背景幅は52px、main (HEAD)の文字は約59.8pxで、さらに左余白5pxを使うため右へ約12.8pxはみ出す。
- 影響: 現在位置を示す文字が背景からはみ出し、読みにくい。
- 対応: HEADを含む実際のラベル文字列に合わせて背景幅を求める。
- 推奨: `$impeccable layout`。

### P2: モバイルで履歴操作後のHEADが画面外になる

- 場所: src/components/git-graph.tsxの固定した最低800pxのSVGとスクロール位置。
- 再現: 「修正コミットを吸収」を対話的rebaseで完了する。
- 実測: 390px画面でHEADの背景はx=396から。画面に完了表示はあるが、最新コミットとHEADは横スクロールしないと見えない。
- 影響: 履歴操作でどこへ移ったかを、その場で確認しにくい。
- 対応: HEAD更新時に表示位置へスクロールするか、全体表示・ズームなどを用意する。意図したグラフ内部のスクロールとページ全体のはみ出しは区別する。
- 推奨: `$impeccable adapt`。

### P2: 一部のタップ領域が小さい

- 場所: やり直しボタン、ファイル一覧、競合の採用ボタン。
- 実測: やり直し32×32px、Cancelの高さ28px、Accept Current/Incoming/Bothの高さ26px。
- 影響: 指で押す際に狙いにくい。操作はできる。
- 対応: モバイルで約44pxの高さを確保し、近接する操作の間隔を広げる。44pxは操作しやすさの改善目標であり、この寸法だけでWCAG AA違反とは断定しない。
- 推奨: `$impeccable adapt`。
