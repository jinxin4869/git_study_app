# 画面監査への対応とE2Eテスト（2026-10-03 JST）

PR #2マージ後のmain（`228e1eb`）から `fix/ui-audit-and-playwright` を作成した。
[修正前の監査記録](browser_ui_audit.md)の5項目を対象とする。

## 対応内容

| 指摘 | 対応 |
| --- | --- |
| 状態凡例・HEADラベルのコントラスト | 凡例を明るくし、HEAD背景を濃くした。ブラウザで計算した両者のコントラストが4.5以上であることを検証する |
| フッターと開始ボタンの重なり | フッターを通常の文書フローへ戻し、間隔を確保した |
| HEADラベルの幅不足 | HEADの接尾辞・非ASCII文字を含む全文字列に応じて背景幅を確保し、SVGの寸法もラベルに合わせる |
| 履歴操作後のHEADの見切れ | HEADが変わった際、表示範囲外ならグラフ内部をスクロールする。コマンド実行によるページ全体のスクロールは行わない |
| 小さいタップ領域 | やり直し・ファイル一覧・競合解決ボタンを44px以上にし、狭い画面では競合の両側を縦に並べる |

既存の配色・構成・学習内容を維持した。競合の採用後に有効になるボタンも、文字を読みやすい濃い背景にした。

## 自動テストとCI

`@playwright/test`、`playwright.config.ts`、`e2e/learning.spec.ts`を追加した。
Vitestの対象をsrc内のテストに限定し、Playwrightのテストを別に実行する。
出力画像・レポートはGitとESLintの対象から除外した。

Chromiumの1440×1000・390×844・320×640・1024×768の4サイズで、7ケースずつ計28ケースを実行する。

- ホームのフッター位置と演習画面への移動
- 検索・該当なし・達成・コマンド履歴・キーボードでのプレビュー・やり直し
- 採用前の完了拒否、採用後の競合解消・コミット作成
- todo編集による対話的rebaseの達成、HEAD全体の表示、文字コントラスト
- 長いブランチ名・Detached HEADの表示
- 部分ステージングの達成
- 承認だけでもCIだけでも足りない模擬PRのマージ条件

全ケースでブラウザのJavaScript例外がないことを検証する。
本番ビルドをテストし、ローカルサーバーの起動・終了をPlaywrightが管理する。
実行手順はREADMEに記載した。

GitHub Actionsではmainへのpush・PRでlint、型チェック、ユニットテスト、ビルド、E2Eを実行し、HTMLレポート・画像・失敗時のトレースを14日間保存する。
CIはヘッドレスで実行し、ローカルでは表示付きブラウザも使用できる。
設定は[Playwrightのサーバー設定](https://playwright.dev/docs/test-webserver)と[CIの公式手順](https://playwright.dev/docs/ci-intro)を確認した。
